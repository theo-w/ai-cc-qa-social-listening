# 规范评审检查清单（Gate-0 / Gate-1）

> 用途：SDD 文档冻结前、实现启动前逐项检查。评审人：Lead + 对应模块 owner。全部勾选方可进入下一阶段。

## A. 文档完整性

- [ ] 文档信息（项目名、版本、作者、日期、状态）齐全
- [ ] 一句话价值主张与「不做什么」边界明确
- [ ] 用户角色、场景、流程图完整
- [ ] 模块功能需求有编号（FR-*）且可测试
- [ ] 非功能需求有编号（NFR-*）且给出验收方法
- [ ] 指标口径表：定义、公式、目标、数据来源、频率齐全
- [ ] MVP 范围与里程碑、风险与应对明确
- [ ] 术语表与数据字典存在且与 PRD 一致

## B. 需求质量

- [ ] 每条 FR 有 Given/When/Then 验收场景
- [ ] 无「快速/友好/智能/尽量」等不可测表述
- [ ] 无 TBD、待定、后续补充
- [ ] 需求之间无冲突（如两个页面要求不同口径）
- [ ] 边界条件（空数据、重复操作、非法状态、权限）已定义
- [ ] 明确的「不做什么」防止范围蔓延

## C. 契约一致性

- [ ] `contracts/openapi.yaml` 通过 lint/validate（0 error）
- [ ] 所有 FR 涉及的字段在 OpenAPI 中存在
- [ ] 枚举值与 `004-data-model.md`、`/api/meta` 设计一致
- [ ] 错误码与错误体结构统一
- [ ] 分页/排序/筛选参数命名统一（q/page/pageSize/sort）
- [ ] 状态机转移表与 API 动作一一对应
- [ ] fixtures 样例与 schema 可互相验证

## D. 数据与评测

- [ ] 数据集 schema、定额、金标字段已冻结
- [ ] 评测指标公式可复算（分子/分母/样本口径明确）
- [ ] 门禁阈值与 PRD 目标一致（80%/15%/90%/70%/30min/2h）
- [ ] 评测回放规则（聚簇、匹配键、边界）明确
- [ ] 数据隐私与脱敏规则明确

## E. 可实施性

- [ ] 技术栈、端口、目录结构、依赖上限明确
- [ ] 任务卡有 owner、写作用域、AC、依赖
- [ ] 任务间无写作用域冲突
- [ ] 演示路径存在且可在 10 分钟内走完
- [ ] 风险清单每条有缓解措施
