# 007 · 评测规范（Evaluation Spec）

| 项 | 内容 |
|---|---|
| 版本 | v0.1.0 |
| 状态 | 冻结（标签口径与指标公式为 MVP 基线） |
| 依赖 | `004-data-model.md` §7 数据集格式 |
| 产物 | `data/` 评测集、`apps/api` 评测引擎、`/eval` 页面、评测报告 |

> 本规范同时是**标注规范**与**指标口径**。数据、引擎、看板、报告必须使用同一口径，否则数字不可比。

## 1. 评测对象与执行方式

| 项 | 定义 |
|---|---|
| 被测对象 | `rule-engine` 检测引擎（质检 + 舆情） |
| 执行入口 | ① 页面「评测中心」点击运行；② `pnpm eval`（CLI，输出 JSON + 控制台摘要） |
| 输入 | `data/qc/dataset.json`、`data/sentiment/dataset.json`（只读） |
| 输出 | `EvalRun` 持久化 + 控制台报告；历史 run 可在页面回看 |
| 可重复性 | 同一数据集 + 同一引擎版本结果完全一致（确定性引擎，无随机） |
| 记录 | 每次 run 保存 datasetVersion、modelVersion、runAt、durationMs、错例 |

## 2. 数据集规范

### 2.1 规模与构成

| 域 | 条数 | 构成 | 版本 |
|---|---|---|---|
| 质检 | 60 | 违规 40（含多标签）、正常 20；低置信度边界 ≥ 10 | `qc-eval-v0.1` |
| 舆情 | 120 | 负面 ≥ 60、中性/正面 60；按主题×日期成 12-16 簇；噪声 ≥ 8 | `sentiment-eval-v0.1` |

### 2.2 质检标签覆盖配额

| 标签 | 最少条数 | 说明 |
|---|---|---|
| `attitude` | 8 | 含显式辱骂/嘲讽与隐晦冷淡两类 |
| `forbidden` | 8 | 含索评、站外、私下交易、绝对化承诺 |
| `off_topic` | 7 | 问题与回答意图不匹配 |
| `wrong_knowledge` | 7 | 费率/时间/规则类事实错误 |
| `timeout` | 6 | 坐席回复间隔 > 180s |
| `escalation` | 6 | 用户情绪升级（投诉/曝光/退款维权） |
| pass（正常） | 20 | 含已解决问题的正常对话 |

> 多标签共现（如 `attitude` + `escalation`）计入各标签配额；每条违规对话必须有且仅有一个 `primaryTag`。

### 2.3 舆情簇配额

| 期望级别 | 簇数 | 每簇条数 | 说明 |
|---|---|---|---|
| P0 | ≥ 2 | 5-10 | 含外挂/回档/充值损失/维权等强信号；至少 1 簇由聚合升级产生 |
| P1 | ≥ 3 | 4-8 | 版本/Bug/活动/客服集中负面 |
| P2 | ≥ 3 | 3-6 | 一般抱怨、建议 |
| none | ≥ 3 | 3-6 | 正面/中性/噪声 |

### 2.4 数据来源与合规

- 全部为**合成数据**（场景模板 + 变量生成），不包含任何真实用户信息；手机号/订单号/昵称一律虚构或打码。
- 生成脚本：`data/scripts/generate.mjs`；生成后由产品按本规范人工抽检 ≥ 10%，抽检记录写入 `data/README.md`。
- 版本管理：修改任何标签或样本 → 版本号 +0.1，旧版报告保留；标签口径变更（§3/§6 规则变化）视为 Major，需重跑并对比历史。

## 3. 质检标签判定规则（标注口径）

> 判定单位：一条完整对话。命中任一规则即 `verdict=violation`；证据必须能在原文定位。

| 标签 | 判违规条件（满足其一） | 不算违规的情况 |
|---|---|---|
| `attitude` 服务态度 | 辱骂、人身攻击、嘲讽反问（"你自己不会看？""这都不懂？"）、指责用户、驱赶（"爱要不要"）、明显不耐烦 | 中性确认、必要提醒、合规拒绝 |
| `forbidden` 违规话术 | 索要好评分、引导站外/私下交易、承诺无法兑现（"包退""百分百解决"）、泄露他人隐私、诱导充值返利 | 正常介绍官方活动、合规收集必要信息 |
| `off_topic` 答非所问 | 回答与用户问题意图不匹配（问 A 答 B）、答非所问式模板回复、连续 2 轮未回应核心诉求 | 先安抚再回答、需要用户补充信息 |
| `wrong_knowledge` 知识错误 | 与知识库事实冲突：错误费率/返还比例、错误活动时间、错误退款规则、错误版本信息 | 不确定时明确转人工/核实，不构成错误 |
| `timeout` 响应超时 | 任一坐席回复间隔 > 180 秒（用户未结束会话） | 用户主动离开、系统维护公告、间隔 < 180s |
| `escalation` 情绪升级 | 用户从平静转为愤怒、出现投诉/曝光/监管/退游/退款维权表述 | 开场即负面但全程情绪平稳 |

**标注复杂度分档**（用于低置信度边界样本）：

- `explicit`：出现明确关键词，人类可一眼判断（引擎应高置信度）。
- `implicit`：需要结合上下文推断（如连续 2 轮答非所问、隐晦嘲讽），引擎应低置信度或转复核。
- 数据中 `implicit` 样本 ≥ 10 条；标注仍必须给出明确 `labels`，`note` 写判断依据。

## 4. 质检指标（MET-QC-*）

记评测集 N 条，`gt` 为标注，`pred` 为引擎输出：

| ID | 指标 | 公式 | 目标 | 说明 |
|---|---|---|---|---|
| MET-QC-COV | 质检覆盖率 | 已检测对话数 / 导入对话数 | ≥ 90% | 引擎全量处理，种子数据为 100%；生产口径按导入批次统计 |
| MET-QC-ACC | 质检准确率（主指标） | 判定一致条数 / N；判定一致 = verdict 相同 **且**（pass，或 primaryTag 相同） | ≥ 80% | 违规但主标签不同视为不一致 |
| MET-QC-VACC | 结论准确率 | verdict 相同条数 / N | 展示用 | 辅助定位"标签错 vs 结论错" |
| MET-QC-FP | 误报率 | 正常被判违规条数 / 预测违规总条数 | ≤ 15% | 分母为 0 时记 0 |
| MET-QC-FN | 漏报率 | 违规未判出条数 / 标注违规总条数 | ≤ 20% | |
| MET-QC-REV | 人工复核占比 | needsReview 条数 / N | ≤ 30% | 演示数据目标 15%-30% |
| MET-QC-LAT | 单条检测耗时 | 总耗时 / N（ms） | < 50ms（本地） | 评测报告展示 |
| MET-QC-TAGP | 标签精确率（分标签） | 预测该标签中正确的比例 | 展示用 | 用于错例分析 |

**混淆矩阵**（四格）：`tp` 违规判违规、`fp` 正常判违规、`tn` 正常判正常、`fn` 违规判正常。**通过标准**：MET-QC-ACC、MET-QC-FP、MET-QC-FN 三项同时达标。

### 4.1 知识库覆盖与完善指标（MET-KB-*，009）

| ID | 指标 | 公式 | 目标 | 说明 |
|---|---|---|---|---|
| MET-KB-LINK | 知识错误关联率 | 带 `knowledge` 引用的 `wrong_knowledge` 标签数 / 全部 `wrong_knowledge` 标签数 | ≥ 90% | 发布会提升；缺口会拉低 |
| MET-KB-GAP | 知识缺口数 | 未关联规则组数 + 未关联知识类 badcase 数 | 趋势下降 | 运营周会跟踪 |
| MET-KB-PUB | 知识发布率 | `published` 条目数 / 全部条目数 | ≥ 70% | 演示种子 7/9 |
| MET-KB-CLOSE | 知识完善闭环率 | 关联了已发布条目的知识类 badcase 数 / 知识类 badcase 总数 | ≥ 70% | 以 badcase 闭环证明中的 KB 编号为准 |
| MET-KB-RECHECK | 复测生效数 | publish/offline 后标签或知识引用发生变化的未复核会话数 | 展示用 | 复测接口返回 |

> 知识库指标只作用于质检域；不改变 MET-QC-* 的分母与门禁。评测集回放时使用**种子中的已发布条目**，因此同一数据集 + 同一知识库版本结果确定。

## 5. 舆情指标（MET-SEN-*）

| ID | 指标 | 公式 | 目标 |
|---|---|---|---|
| MET-SEN-SA | 情感分类准确率 | sentiment 相同条数 / N | ≥ 80% |
| MET-SEN-TA | 主题分类准确率 | primaryTopic 相同条数 / N | ≥ 75% |
| MET-SEN-AP | 预警准确率（precision） | 预测预警中级别与期望一致数 / 预测预警总数 | ≥ 80% |
| MET-SEN-AR | 预警召回率 | 级别与期望一致的预警数 / 期望预警总数 | ≥ 80%（展示） |
| MET-SEN-P0R | P0 召回率 | 命中 P0 预警数 / 期望 P0 预警数 | ≥ 90%（展示） |
| MET-SEN-REV | 舆情复核占比 | needsReview 评论数 / N | 展示（目标 ≤ 30%） |

**预警回放口径**（关键）：

1. 按 `primaryTopic + publishedAt 日期` 将评论聚合成簇（引擎预测主题用于回放，期望簇用标注主题）。
2. 单条级别：按 §6 规则由标注 `expectedLevel` 或引擎 `severity` 得出。
3. 簇级别 = `max(单条级别, 聚合升级级别)`；聚合升级：负面条数 ≥ 8 → P0，≥ 3 → 至少 P1，≥ 1 → 至少 P2。
4. 期望预警集合 = 期望簇级别 ∈ {P0,P1,P2} 的簇；预测预警集合同理。
5. 匹配键 `(topic, date)`；匹配上且级别相同计 true positive；预测有而期望无计 false positive；期望有而预测无计 false negative。

## 6. 舆情分级规则（标注与引擎共用）

### 6.1 单条评论级别

| 期望级别 | 判定条件（满足其一） | 示例信号 |
|---|---|---|
| P0 | 负面 **且** 命中高危主题（外挂/充值/版本）**且** 出现高危信号词：回档、封号误封、扣款不到账、无法登录、大面积、集体、维权、投诉、12315、媒体曝光、退款潮；或明确资损/数据丢失 | "回档了，充的钱全没了，去12315投诉" |
| P1 | 负面 **且** 命中主题（版本/Bug/活动/客服/充值）且描述明确影响（无法使用、异常、拖延、态度差）；无 P0 信号 | "新版本一直闪退，根本没法玩" |
| P2 | 负面或中性的抱怨、建议、体验反馈；无 P0/P1 信号 | "希望活动多一点" "客服回复有点慢" |
| none | 正面、中性无行动价值、噪声（广告/灌水/无关） | "好玩，推荐" |

### 6.2 聚合升级（按主题×日期）

| 条件 | 升级结果 |
|---|---|
| 簇内负面 ≥ 8 条 | 簇级别 = P0 |
| 簇内负面 3-7 条 | 簇级别 ≥ P1 |
| 簇内负面 1-2 条 | 簇级别 ≥ P2 |
| 簇内负面 0 条 | 簇级别 = max(单条级别)（通常 none） |

### 6.3 预警责任人与 SLA

| 级别 | 首次响应 SLA | 默认责任人 | 通知范围（演示） |
|---|---|---|---|
| P0 | 30 分钟 | 江岚（品牌，主责）；通知：陆川（主管）、周野（产研） | 品牌/主管/产研 |
| P1 | 2 小时 | 按主题路由（见 004 §4.5） | 品牌/主管 |
| P2 | 24 小时 | 按主题路由 | 观察池 |

## 7. 合格判定与发布门禁

| 门禁 | 条件 | 不通过处理 |
|---|---|---|
| G-EVAL-1 | 质检 MET-QC-ACC ≥ 80% 且 MET-QC-FP ≤ 15% 且 MET-QC-FN ≤ 20% | 调整规则或标注，重跑；不得静默发布 |
| G-EVAL-2 | 舆情 MET-SEN-SA ≥ 80% 且 MET-SEN-TA ≥ 75% 且 MET-SEN-AP ≥ 80% | 同上 |
| G-EVAL-3 | 复核占比 MET-QC-REV ≤ 30% | 调整置信度阈值 |
| G-EVAL-4 | 评测可重复：同数据同版本连续两次 run 指标完全一致 | 修复引擎随机性 |
| G-EVAL-5 | 错例清单 ≤ 20 条且包含 expected/predicted/reason | 补错例分析 |

> 发布声明（README/演示）必须附：`datasetVersion`、`modelVersion`、run 时间、指标表、达标结论。未达标需在报告中写明原因与下一步。

## 8. 标注流程与质量控制

1. 规则冻结（本文件 Gate 2 通过）。
2. 数据脚本生成 → 自动校验（条数、配额、枚举、时间单调、证据文本存在）。
3. 人工抽检 ≥ 10%：检查标签与证据一致性；记录抽检人/日期/结论到 `data/README.md`。
4. 引擎运行 → 错例分析 → 区分"标注错"与"引擎错"：标注错则修数据升版本，引擎错则改规则。
5. 每周复测一次；标签/规则变更后强制复测。

## 9. 错例分析模板

```markdown
### 错例 {itemId}
- 期望：verdict=violation, primaryTag=off_topic,（证据 seq=6）
- 预测：verdict=pass，置信度 0.71
- 根因：坐席回答"已反馈"未回应用户退款诉求；引擎未建立"连续未回应核心诉求"规则
- 归因类型：引擎漏报 / 标注错误 / 规则边界
- 处理：新增规则 OT-04；回归后重跑评测
```
