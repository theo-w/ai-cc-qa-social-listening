### 1.2 讲解前的三个口径（全程不夸大）

1. **数据口径**：全部为合成评测数据 + 确定性规则引擎，无外部 API、无真实模型训练；指标用于验证工程可复现性，**不代表线上泛化能力**。
2. **AI 结论口径**：质检结果是「AI 初判」，带置信度；低置信度进人工复核，AI 不替代人做最终判定。
3. **门禁口径**：007 的 G-EVAL 门禁是内部发布条件，不是业务效果承诺；未达标就直说并给整改路径（见第 4 节）。

## 4. 指标口径与门禁解释（演示话术）

### 4.1 先讲口径，再讲数字（三句话，固定顺序）

1. 「评测集是**合成数据 + 人工金标**，引擎是**确定性规则引擎**；指标证明的是可复现的工程质量，不是线上泛化能力。」
2. 「门禁是**内部发布条件**，通过也不代表线上业务效果，未通过也不代表不可演示——它说明下一步改什么。」
3. 「所有指标、错例、历史 run 都能在评测中心与 `docs/metric-dictionary.md` 对齐口径。」

### 4.2 达标时怎么说（示例话术，按页面实际数字替换）

| 场景 | 话术模板 | 禁止说法 |
|---|---|---|
| 质检门禁通过 | 「G-EVAL-1 三项同时达标：准确率 ___% ≥80%、误报率 ___% ≤15%、漏报率 ___% ≤20%，因此质检评测门禁结论为通过。」 | 「AI 质检准确率 ___%，线上直接可用」 |
| 复核占比达标 | 「G-EVAL-3：人工复核占比 ___% ≤30%，说明大部分样本由 AI 初判直接处理。」 | 「以后不需要人工复核」 |
| 一致性 | 「G-EVAL-4：同一数据集、同一引擎版本连续两次运行，指标完全一致，结果可复现。」 | 「指标会自己越来越好」 |
| 舆情门禁通过 | 「G-EVAL-2：情感准确率 ___% ≥80%、主题准确率 ___% ≥75%、预警准确率 ___% ≥80%，三项达标。」 | 「舆情预警 100% 不漏报」 |

### 4.3 未达标时怎么说（同一套结构：口径 → 数字 → 原因 → 下一步）

| 场景 | 话术模板 |
|---|---|
| 某项指标低于目标 | 「这一项在本次评测集上**未达标**：例如复核占比 ___% 高于 ≤30% 的目标。原因是低置信边界样本较多、阈值偏保守；错例清单已列出具体的期望/预测/原因。下一步调整置信阈值或补金标后复测，这不是线上结论。」 |
| 只有部分门禁通过 | 「G-EVAL-1/3/4 的通过项见徽标；未通过项不做美化，按门禁结论记录，作为下一轮迭代输入。」 |
| 数据/引擎变化后复测 | 「先用 `pnpm reset` 回到确定态再复测；同数据同引擎版本结果不会漂移（G-EVAL-4）。」 |

### 4.4 门禁对照表（讲解时口述，页面 `/eval` 展示）

| 门禁 | 指标与阈值 | 演示入口 |
|---|---|---|

| G-EVAL-2 | 舆情：MET-SEN-SA ≥80%、TA ≥75%、AP ≥80% | `/eval` 舆情指标表与门禁徽标 |

## 5. 故障兜底

| 现象 | 快速检查 | 处置 |
|---|---|---|
| 页面打不开 / 白屏 | 终端 `pnpm dev` 是否仍在运行；5178 是否被占用 | 重启 `pnpm dev`；端口冲突时按 Vite 输出端口访问，勿改端口 |
| 接口全部报错 | 访问 `/api/health`；API 8787 进程是否存活 | 重启 `pnpm dev`；确认 `pnpm start` 未与 `pnpm dev` 抢占 8787 |
| 数据被点乱 / 状态不对 | 侧边栏版本、各列表计数是否异常 | 顶栏「重置演示数据」→ 确认；或终端 `pnpm reset`；reset 是确定性的，可重复执行 |
| 提交动作报 409/422 | Toast/表单下方红字提示 | 这是状态机与校验拦截（如重复复核、关闭未填证明），按提示补齐或 reset，不要手改数据文件 |
| 评测运行很久或失败 | 指标区是否出现错误态；API 日志 | 使用历史 run 的结果讲解；修复后重新「运行评测」，同数据结果一致 |
| 现场网络/投影异常 | 无需外网（无外部 API） | 本地直接演示；字体走系统字体，不依赖网络 |
