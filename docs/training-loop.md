# 培训闭环（Training Loop）

> 适用：QCC Workbench MVP 从「质检/舆情发现问题」到「培训改进并复测验证」的闭环机制。
> 依据：`specs/007-evaluation-spec.md` §3（标注口径）、§7（门禁）、§8（标注流程）；`specs/004-data-model.md` §4.2（归因）、§5.1（Badcase 状态机）；关联模板：`docs/badcase-template.md`、`docs/metric-dictionary.md`。
> 目标：让每一条重复出现的服务问题，都能落到「谁、学什么、怎么验」，而不是只停留在扣分。

## 1. 闭环总览

```text
发现 ──▶ 归因 ──▶ 培训 ──▶ 复测 ──▶ 固化
 │         │         │         │         │
 │ 质检违规 │ knowledge │ 课程/话术 │ 抽测+评测回归 │ 知识库/话术/SOP 更新
 │ 复核改判 │ script    │ 1v1/班课  │ 指标对比      │ 培训档案沉淀
 │ 舆情P0/P1│ process   │ 流程演练  │ badcase验证   │ 下轮抽检
 └ 看板异常 │ system    │ 转产研    │ 复发检查      │
```

| 阶段 | 负责人 | 产出 | 时限 |
|---|---|---|---|
| 发现 | 质检/复核/舆情值班 | badcase、错例、预警 | 当日 |
| 归因 | 质检组长 + 对应责任人 | `category` 与根因 | 1 个工作日 |
| 培训 | 唐沐（培训）/顾清（知识）/陆川（流程） | 培训记录、话术/知识更新 | high 48h 内，medium 5 个工作日内 |
| 复测 | 质检组 | 抽测结果、评测 run | 培训后 3 个工作日内 |
| 固化 | 责任人 | 状态机 closed + proof | 复测通过后 |

## 2. 输入源与去重

| 输入 | 数据来源 | 进入培训闭环的条件 |
|---|---|---|
| 质检违规 | `data/qc/dataset.json` 金标 + 运行态 QcResult | 同一坐席同类标签 7 天内 ≥ 2 次，或 high 标签 1 次 |
| 复核改判 | ReviewTask（`decision=overturn/amend`） | 暴露规则/话术/培训缺口 |
| 评测错例 | `EvalRun.mismatches`（≤ 20 条） | 归因为「引擎错」修规则；归因为「标注错」修数据；归因为「口径不清」补培训 |
| 舆情 P0/P1 | SentimentAlert（簇级别） | 涉及客服口径/流程/知识时转培训或流程改进 |
| 看板异常 | DashboardAnomaly | 指标连续 2 天未达标且归因到服务执行 |

去重规则：同一 `category + rootCause + 坐席/班组` 合并为一个培训主题；已在培训中的问题新样本只追加到培训记录，不重复开课。

## 3. 归因到培训内容的映射（004 §4.2）

| category | 典型问题 | 培训内容 | 讲师/负责人 | 复测方式 |
|---|---|---|---|---|
| `knowledge` | 费率/时间/规则答错 | 知识库条目讲解 + 场景问答 | 顾清 | 知识题 10 题 + 抽 5 条对话 |
| `script` | 嘲讽、违规承诺、索评、站外引导 | 话术红线 + 正反例演练 | 唐沐 | 抽 5 条对话 + 角色扮演 |
| `process` | 超时、工单拖延、转接混乱 | 流程 SOP 走查 + 系统操作 | 陆川 | 流程节点抽检 |
| `system` | 工具缺陷、系统报错 | 转产研，不列入培训 | 周野 | 回归修复版本 |

## 6. 复测与效果验证

### 6.1 单次培训复测

| 项 | 要求 |
|---|---|
| 样本量 | ≥ 5 条同类标签对话（不足时用补造场景）+ 3 条正常对照 |
| 通过标准 | 同类违规不再出现，且正常样本不误判；人工复核确认 |
| 记录位置 | badcase 的 `proof` 与 timeline；培训记录附件 |
| 不通过处理 | `pending_verify → in_progress`，补训或调整流程后再验 |

### 6.2 指标级验证（累计效果）

| 指标 | 口径 | 观察周期 | 通过参考 |
|---|---|---|---|
| MET-QC-ACC | 见 `docs/metric-dictionary.md` | 每次规则/培训变更后 | ≥ 80% 且不下降 |
| MET-QC-FP / FN | 同上 | 培训后首次全量 | ≤ 15% / ≤ 20% |
| MET-QC-REV | needsReview 占比 | 每周 | ≤ 30%（演示目标 15%–30%） |
| 同类标签违规率 | 该标签违规对话数 / 该坐席会话数 | 7 天、14 天对比 | 较培训前下降 ≥ 50% |
| badcase 复发率 | recurrence=true 数 / badcase 总数 | 30 天 | 下降趋势，重点 case 不复发 |
| badcase 闭环率 | closed / total | 每周 | ≥ 70% |
| CSAT / 满意度 | 会话满意度均值 | 每周 | 不下降 |

> 对比方法：培训前后各取 7 天同口径数据；样本不足时只做定性结论，不强行给百分比。

## 7. 与 Badcase 状态机的衔接

```text
in_progress（培训计划制定/执行） ──提交──▶ pending_verify（复测） ──通过+proof──▶ closed
        ▲                                        │
        └────────────不通过，补训────────────────┘
closed ──7 天内同标签同根因复发──▶ in_progress（recurrence=true）
```

- 培训类 badcase 的 `proof` 必须包含：培训记录 id、考核通过率、复测结果（对应 004 §5.1「关闭必须提供 proof」）。
- 复发重开时在 timeline 注明复发原因（人员/流程/知识未更新），并优先复用原培训材料。
- 质检复核改判（overturn/amend）不计入坐席过错，但若暴露口径不清，仍应补培训并更新话术。

## 8. 运营节奏

| 节奏 | 会议/动作 | 参与人 | 输出 |
|---|---|---|---|
| 每日 | 看异常卡与 P0/P1 预警 | 客服运营值班 | 当日处置/转办 |
| 每周 | 质检周会：违规 TOP 标签、错例、badcase 进度 | 沈言、陆川、唐沐 | 培训计划、规则调整项 |
| 每两周 | 培训复盘：复测结果与指标对比 | 唐沐、顾清、陆川 | 通过/补训/流程变更 |
| 每月 | 月度质量复盘：ACC/FP/FN/复发率/CSAT | 全体责任人 | 下月目标与资源 |

看板口径统一用 `docs/metric-dictionary.md`；评测结论必须附 `datasetVersion`、`modelVersion`、run 时间（G-EVAL 发布声明要求）。

## 9. 常见问题

| 问题 | 表现 | 处理 |
|---|---|---|
| 培训完不验证 | badcase 直接关单 | 必须复测并写 proof，否则不允许 closed |
| 用「态度不好」归因 | 培训无法落地 | 归因到知识/话术/流程/系统的具体缺口 |
| 只培训不更新材料 | 新人再犯 | 同步更新知识库/话术模板/SOP 版本 |
| 指标对比口径不一致 | 效果被质疑 | 用同一指标字典、同一时间窗口、同版本数据 |
| 把系统缺陷当培训问题 | 反复培训无效 | `category=system` 转产研，列入修复回归 |
| 复发不关联历史 | 复发率指标失真 | 7 天内同标签同根因填 `recurrence/recurrenceOf` |

## 10. 模板维护

- 本流程与 004 §5.1、007 §7/§8 对齐；口径变化先改 spec 再改模板。
- 每季度抽样 10 个已闭环培训类 badcase，检查「培训记录 + 复测记录 + proof」三件套完整性，结论纳入质检周会。
